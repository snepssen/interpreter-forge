# Mac and iPhone UI polish — 11 October 2026

The shared SwiftUI screen now gives the conversation, session status and model
settings distinct places. It uses semantic system colors for light/dark
appearance, system text styles and a shared card treatment.

## Changes

- A clear Interpreter header, Ready/Live status and labelled language menu.
  Three or more selected languages use a compact count; the menu and
  accessibility value retain the full selection.
- Translation cards emphasise English, with the original speech underneath.
  English context, echoes, skipped languages and requests to repeat have
  explicit labels. Stopped, unfinished pieces no longer say “Interpreting”.
- Transcript options contain the English-context switch and Clear conversation.
  Clearing remains disabled during a live session. Automatic scrolling respects
  Reduce Motion.
- The iPhone keeps a full-width Live/Stop control at the bottom, with microphone
  status and readable notices above it. Settings/menu controls have 44-point
  targets; Live has a 54-point minimum height.
- Mac microphone/output pickers have explicit labels and flexible widths.
  A new window defaults to 780 × 720 points, with a 520-point minimum width.
- Model names occupy their own line. Recommendation/selection badges can wrap
  separately, download size has its own label, and download progress is named.
  Recognition storage is a separate card. Delete still asks for confirmation.

## Verification

The rebuilt Mac app was visually inspected in dark appearance. Ready, Live,
Stop, a populated speech card, the model manager and clearing a stopped
conversation were checked in the actual app. The user confirmed the installed
phone remains live for at least twenty seconds and displays speech without the
route warning after the audio-startup repair.

The shared package suite passed **25 tests**, and the Mac core passed **53
checks**. The Python suite passed **65 tests**; its three installer checks were
also rerun after changing the iOS scheme. Both Release products were generated
and signed. The iOS app builds through the explicit `InterpreterPhone` scheme,
which avoids selecting the Swift package's similarly named executable.

This pass does not establish every Dynamic Type size, VoiceOver flow, device
route or translation's conversational accuracy. Remaining physical acceptance
is recorded in the [engine review](code-review-2026-10-11.md).
